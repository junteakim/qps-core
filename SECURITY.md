# Security Policy

## Supported version

Security fixes are applied to the latest release on the default branch.

## Reporting

Use GitHub private vulnerability reporting for suspected vulnerabilities. Do not open a public issue that contains credentials, personal data, customer data, or exploit details.

## Data boundary

Pull requests must use synthetic fixtures. Real emails, quotations, drawings, customer names, vendor names, credentials, and licensed codebook extracts are not accepted.

# 보안 정책

## 지원 버전

보안 수정은 기본 브랜치의 최신 릴리스에 적용합니다.

## 신고

취약점이 의심되면 GitHub 비공개 취약점 신고 기능을 사용하십시오. 자격증명, 개인정보, 고객 데이터, 공격 세부사항이 포함된 공개 이슈를 만들지 마십시오.

## 데이터 경계

Pull request는 합성 fixture만 사용해야 합니다. 실제 메일, 견적, 도면, 고객명, 벤더명, 자격증명, 라이선스가 필요한 코드북 발췌문은 허용하지 않습니다.
